# SEO/AEO Phases 2-4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the pages that rank and get cited for commercial insurance agency owners (3 answer pages + public-data market pages), the proof rows they may quote, the citation pitches, and a monthly AI-visibility check. Nothing ships live without Max's copy approval and deploy go.

**Architecture:** One shared page registry (`lib/site-pages.ts`) feeds the sitemap, `llms.txt` and the homepage footer links, so no page is ever orphaned. Answer pages are static Next.js routes built on a shared `AnswerPage` layout with FAQ JSON-LD. Market pages are statically generated from aggregate JSON files built offline by a Python script from free public data (FMCSA, Texas DWC). Proof rows, pitches and the visibility script live in the ops repo.

**Tech Stack:** Next.js 15 app router, React 19, Tailwind, Vitest + Testing Library (site repo). Python 3 + `_system/scripts/lib/gov_registries.py` (ops repo).

**Spec:** `docs/superpowers/specs/2026-11-15-seo-aeo-strategy.md` (copy of `knowledge_base/maxionlabs-acquisition/seo-aeo-strategy.md`, status approved).

**Repos:**
- SITE = `~/maxionlabs-landing/gtm-landing-page-seo/gtm-landing-page`, branch `max-738-seo` from origin/main `9535347`. node_modules is a symlink, so build with `npx next build --webpack`.
- OPS = `~/gtm-context-os-quickstart` (shared tree, other sessions commit here).

- No em dashes (U+2014) in any rendered markup or outward copy.
- Never render a client or prospect name: Cosmo, Heritage, Pearsall, Stiltner, Herschlag, Gabbel, Strong Tower, Connie, Jeremy. Roles, lines and states only.
- Numbers about our results come only from a `QUOTABLE` row in OPS `knowledge_base/maxionlabs-acquisition/proof/funnel-tracker.md`. Offer numbers come only from OPS `00_foundation/offer-v3.md`: $4,725/month, $12,500 for 90 days, 15 qualified meetings a month, $315 per missed meeting, 7-day full refund, month to month.
- Never on the site: the $500 deposit, "pay per meeting", "Step-down", "win-back", "Cross-sell", "trades, insurance and lending".
- Burn words never used as our own category: "leads" (as what we sell), "telemarketer", "appointment setting" (allowed only inside a quoted search phrase or a comparison).
- Market pages show aggregates only. No business name, DOT number, EIN, address or phone from public data on any page.
- Every new public route is registered in `lib/site-pages.ts`; nothing in the sitemap is in the robots disallow list.
- Copy is drafted by a Fable subagent (`model: fable`) from the research files named in each task; code tasks run on Sonnet. Copy structure from cited pages, never wording.
- Commits: explicit file list, count-check and commit in one command, message carries `Linear: MAX-738` and ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never `git add -A`.
- No push, deploy, send or pitch without Max's go in chat.

## Review Focus

1. A market data file with too few records (e.g. a state with 9 new trucking authorities) must not generate a thin page: below `MIN_RECORDS = 25` the route 404s and drops out of the sitemap. Test in Task 6.
2. Stale data must not claim freshness: a market page shows the data file's `asOf` date, and if `asOf` is more than 45 days before the build date it says "as of <date>" and never "this month". Test in Task 6.
3. A new page that slips a banned term, client name or em dash. One shared test sweeps every registry route (Task 1, re-run in Task 9).
4. A route that exists but is not in the registry (orphan) or a registry entry with no route (404 in sitemap). Test in Task 9 renders every registry path.
5. Public data JSON carrying identifying fields. The build script whitelists output keys and the site test rejects any file with a key outside the schema (Tasks 5 and 6).
